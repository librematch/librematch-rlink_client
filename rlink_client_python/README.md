## Positional arrays

`/game` uses `application/x-www-form-urlencoded` bodies and **positional
JSON arrays**: the meaning of a slot comes from its index, not from a key,
and OpenAPI objects cannot express that. The operations declare
`x-response-positions`: a list with one entry per slot, in order, each
entry being an object with the slot `name`, a `description` of its JSON
type and semantics, its expected `value` when it is a constant, and the
`row` it repeats when it is an array (the row is documented once, slot by
slot, in `#/components/schemas/<row>`). The response schema itself is
always `Positional`. The `/community` API uses named-field JSON objects,
except where its rows reuse the same positional encodings.

## Requests

* GET: fields are bound from the query string.
* POST: fields are bound from the `x-www-form-urlencoded` body; with a
  `Content-Type: application/json` request the body is decoded as JSON.
  Unknown keys are ignored, so the fields the clients send and the service
  does not read (always listed in each description) do not fail the call.
* Responses are `Content-Type: application/json;charset=utf-8` with a
  trailing newline (the raw signed catalogue bodies are the exceptions).

## Authentication

* `/game`: the `sessionID` returned by `POST /game/login/platformlogin`
  (its `connectionToken`), sent in the form body or in the query string.
  A missing or unknown one gets `401 Unauthorized` (plain text). The
  routes that are exempt declare `security: []`:
  `/game/login/platformlogin`, `/game/news/getNews`,
  `/game/Challenge/getChallenges`, `/game/item/getItemBundleItemsJson`,
  `/game/msstore/getStoreTokens` and `/wss/`.
* `/community`: anonymous; the optional `title` query parameter selects
  the title whose data is answered. A foreign or unknown title answers
  404 with no body, and a missing title on the andromeda host answers 400
  with an HTML error page.

## Hosts

Which host serves which tree (`<tld>` is `.com`): the game hosts are
`aoe-api.reliclink.com` and `aoe-api.worldsedgelink.com` for every title;
the release hosts `pb-live-release<N>-api.worldsedgelink.com` (A2),
`aoeliverelease1/2-api.worldsedgelink.com` and
`dr-activerelease<N>-api.worldsedgelink.com` (A4),
`andromeda-live-release<N>-api.worldsedgelink.com` and
`athens-live-api.worldsedgelink.com` (AoM), plus the A2 macOS hosts
`arthurlive-api.worldsedgelink.com` and
`arthurlive-release<N>-api.worldsedgelink.com`. `<N>` also extends to
further releases when they resolve. They serve `/game` and `/community`.

## Signatures

Several catalogues travel with a `dataSignature` the client verifies with
an RSA-2048 SPKI it carries in its own process. The scheme is the RelicLink
variant of PKCS#1 v1.5 with the bare SHA-512 digest (no ASN.1 DigestInfo)
and maximum-length padding: the body is signed with the decimal ASCII of
`crc32(body-with-the-signature-emptied)` as the input tag, producing a
344-character base64 string. For short-parameter requests the signature is
served raw (`POST /game/item/signItems`).

## Errors

* HTTP `401 Unauthorized` (plain text) for a missing or unknown
  `sessionID`.
* Positional `[2, ...]` result codes are the functional errors of the
  game tree; the constant or per-error content is documented per
  operation.

## Request headers

Header names are compared case-insensitively in all Python client libraries.
Request headers are copied; supplying `_headers` does not change the caller's dict
or the client's shared defaults. The public `_headers` argument retains its dict
validation and existing value serialization. Pydantic can coerce mappings such as HTTPX `Headers` to a dict,
combining repeated fields into a single value; `_headers` does not provide a
repeated-field or list-of-pairs API.

Precedence, from lowest to highest:

1. `_headers` (within one dict, the last inserted case variant wins).
2. Explicit OpenAPI header parameters and generated `Content-Type` (or `_content_type`).
   Generated `Accept` is added only when neither `_headers` nor explicit header
   parameters contain an `Accept` case variant.
3. `ApiClient.default_headers` (including headers set with `set_default_header`).
4. The client's `cookie` setting, for `Cookie`.
5. Authentication headers. A non-empty `_request_auth` replaces configured
   authentication for that call; `{}` retains configured authentication. Cookie
   authentication appends to the selected `Cookie` value.

This retains the existing precedence for identically spelled names and extends it
to case variants. To override a generated content type, use `_content_type`;
client defaults still take precedence over it. The winning header's spelling and
value are retained for replacements. Cookie authentication uses the canonical
`Cookie` spelling and appends its value. Values containing legitimate
comma-separated lists are not split or deduplicated. This does not remove
duplicate values inside a header or change the handling of repeated fields
supplied directly to the transport.
